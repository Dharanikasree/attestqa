Make per-test data isolation required and visible for stateful stories. SCRUM-19's basket tests shared one account and ran one after another, so the product one test added was still in the basket when the next added it — the application answered HTTP 500 and a badge that expected "1" read "2" — and the agent spent nine runs of nine repairing locators instead of isolating the data (W15/W18/W21, F-0097/F-0100/F-0104). `validateDesign` now requires a story that changes shared server-side state (a basket, booking or order) to say, once, how each test gets its own data: a fresh account per test, the state cleared before each test, or a unique datum per test. A review-only verifier check reports a test that mutates shared state when nothing — its own body or a shared `beforeEach` — isolates it. And the skill now tells the agent that a 500 or a wrong count on a stateful setup is a data problem, not a locator problem (isolate it, do not wrap it in try/catch), and that a missing confirmation message is read from the page snapshot, not guessed at with a widened regex. This makes the right behaviour required and visible; whether the agent then isolates well enough to finish a stateful story within budget is a model question, measured in a run. synthdata-backed account generation is a deferred follow-up.
